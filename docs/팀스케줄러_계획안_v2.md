# 엑셀 VBA 팀 스케줄러 계획안 v2 (통합·간소화판)

> v1 계획안(`팀스케줄러_계획안.md`)과 별도 제안안(“기존 캘린더 + TaskDB + VBA 자동동기화 + 팀장 Dashboard”)을 비교해
> **“팀원은 덜 입력하고, 팀장은 버튼 하나로 본다”** 는 기준으로 다시 정리한 계획안입니다.

---

## 0. 한 줄 요약

**주간보고 주기에 맞춘 새 캘린더(월 단위·주 단위 줄)를 TaskDB가 자동으로 그린다. 팀장은 [전체 동기화] 버튼 하나로 모든 화면을 본다.**

```
[팀원]  주간형 월간 Calendar (자동 표시) ⇄ TaskDB (표준 표 1개) → 주간보고 초안 자동 생성
                                        │  저장만 하면 끝
                                        ▼
                             사내 공유폴더 \Member\
                                        │  읽기 전용
                                        ▼
[팀장]  [전체 동기화] 1번 → TaskAll → Dashboard / 프로젝트 보기 / 팀 일정
```

### v2에서 간편해진 점
1. 팀원이 직접 입력하는 칸: **6개** (프로젝트, 업무명, 시작일, 종료일, 진척률, 상태)
2. 팀원이 누르는 버튼: **4개** (새 Task, 월 이동, 이번 주, 주간보고) – 저장하면 캘린더는 자동 갱신
3. 주간보고: 캘린더의 주간 요약을 그대로 **보고서 초안 텍스트**로 만들어 줌 → 복사해서 붙여넣기만
4. 팀장이 누르는 버튼: **1개** ([전체 동기화]) – 나머지 화면은 자동 계산
5. 팀원 추가/삭제: 공유폴더에 파일을 넣고 빼는 것으로 끝
6. 프로젝트 추가: 팀장이 ProjectMaster에 한 줄 추가 → 팀원 파일이 열릴 때 자동 반영
7. 팀원이 새 프로젝트가 필요할 때: 입력폼에서 `[+ 새 프로젝트 요청]` → 바로 Task 입력 가능, 팀장 승인은 동기화 때 한 번에

## 3. 팀원 파일 (`이름_업무일정.xlsm`)

### 3.1 시트 (4개)
| 시트 | 용도 | 보이기 |
|------|------|--------|
| `Calendar` | 새로 설계한 **주간형 월간 달력** – TaskDB를 자동 표시 (3.3) | 보임 (주 화면) |
| `TaskDB` | Task 원본 데이터 (표 이름 `tblTask`) | 보임 (필요 시 직접 수정) |
| `WeeklyReport` | 선택한 주의 **금주 실적 / 차주 계획** 보고서 초안 (3.4) | 보임 |
| `Setting` | 이름, 주 시작 요일·주차 규칙, 상태·우선순위 목록, 프로젝트 목록 캐시, **내 프로젝트 요청 표(`tblMyRequest`)**, 캘린더 메모(`tblMemo`), 팀 공통 보고일정 캐시, 공휴일, 파일 버전 | 숨김 |

### 3.2 TaskDB 열 구조 (`TaskDB!A1:R`, 1행 머리글)
| 열 | 항목 | 구분 | 설명 |
|----|------|------|------|
| A | TaskID | 자동 | `KIM-0001` (이니셜-일련번호), 수정 불가 |
| B | ProjectID | **입력** | 드롭다운 (`P001` …). 프로젝트 외 업무는 `공통`, 휴가는 `휴가`. 승인 전 임시 프로젝트는 `N-김OO-01` 형식 |
| C | ProjectName | 자동 | ProjectID로 조회 |
| D | Phase | 선택 | 드롭다운 (프로젝트별 단계 목록, 비워도 됨) |
| E | TaskName | **입력** | 캘린더에 표시되는 업무명 |
| F | StartDate | **입력** | |
| G | DueDate | **입력** | StartDate 이후만 허용 |
| H | Completion | **입력** | 드롭다운 0/10/25/50/75/90/100 |
| I | Status | **입력** | 예정 / 진행 / 완료 / 보류 / 취소 |
| J | Priority | 선택 | 상 / 중 / 하 (기본 중) |
| K | Note | 선택 | 지연 사유·이슈 → 팀장 지연목록에 그대로 표시 |
| L | Owner | 자동 | Setting의 이름 |
| M | PlanDays | 자동 | 공휴일 제외 작업일수 (진척률 가중치) |
| N | DoneDate | 자동 | 완료 선택 시 오늘 날짜 |
| O | CreatedDate | 자동 | |
| P | LastUpdated | 자동 | 행 변경 시 기록 (팀장이 미갱신 확인) |
| Q | LeaderComment | 자동(읽기 전용) | 팀장 코멘트. 파일 열 때 `ProjectList.xlsx`의 Comments에서 가져옴 (4.7) |
| R | Milestone | 선택 | ☑ 체크 시 **보고·마감 일정**으로 표시 (종료일에 ◆, 캘린더 맨 윗줄 고정) |

**자동 보정 규칙** (사람이 신경 쓸 필요 없게)
- Status=완료 → Completion=100, DoneDate=오늘 / Completion=100 → Status=완료
- Completion>0 인데 Status=예정 → 진행으로 변경
- 필수 6칸 누락 행은 연한 빨강 표시 (저장은 막지 않음)

> 연구소 특화 항목(관련제품, 샘플번호, 결과물, 검토자, 외부기관 등)은 **S열 이후 선택 열**로 3단계에서 추가. 1단계 필수 항목에는 넣지 않는다.

### 3.3 Calendar 시트 – 새 설계: “주간형 월간 달력”

#### 설계 이유
| 요구 | 설계 선택 |
|------|-----------|
| 보고는 **주 단위**(주간보고·주간회의)로 돈다 | 달력을 **한 주 = 한 블록**으로 끊고, 블록마다 `주차`와 **주간 요약 칸**을 둠 → 캘린더 한 줄이 곧 주간보고 1건 |
| 여러 날 걸친 업무가 대부분 | 날마다 글자를 반복하지 않고 **한 줄짜리 막대(bar)** 로 표시 → 기간이 한눈에 보임 |
| VBA가 **자동으로** 정확히 채워야 함 | 모든 주 블록의 행·열 크기가 **완전히 동일한 격자** → 좌표 계산만으로 그림, 병합셀 최소화 |
| 주말엔 업무가 거의 없음 | 토·일은 **좁은 1칸(주말)** 으로 합쳐 평일 칸을 넓게 |
| 보고·마감일을 놓치면 안 됨 | 마일스톤(◆)과 팀 공통 보고일정은 **각 주의 맨 윗줄에 고정** |

#### 셀 배치 (VBA 좌표 기준 – 모든 파일 동일)
| 영역 | 위치 | 내용 |
|------|------|------|
| 제목·버튼 | 1행 | 연월, 이름, 버튼, 범례 |
| 요일 머리글 | 3행 | 주차 / 월~금 / 주말 / 주간 요약 |
| 주 블록 | 4행부터 **9행씩 × 최대 6주** (4~57행) | 블록 1개 = 날짜 1행 + **보고 줄 1행** + **업무 막대 5행** + 메모 2행 |
| 열 | A=주차(폭 7), B~F=월~금(폭 20), G=주말(폭 7), H=주간 요약(폭 30) | |

블록 내부 행 (예: 1주차 = 4~12행)
| 행 | 용도 | 누가 채움 |
|----|------|-----------|
| +0 | 날짜 숫자, 공휴일명, `+n건`(넘친 업무 수) | VBA |
| +1 | **보고 줄**: ◆ 마일스톤(본인 Milestone 체크 Task) + 팀 공통 보고일정(주간회의·월간보고 등, 4.9) | VBA |
| +2 ~ +6 | **업무 막대 5줄** (레인) | VBA |
| +7 ~ +8 | **메모 2줄** – 자유 입력, VBA가 절대 지우지 않음 (날짜별로 TaskDB와 별도 `tblMemo`에 저장해 월을 넘겨도 유지) | 팀원 |
| H열(+0~+8 병합) | **주간 요약** | VBA |

#### 업무 막대(bar) 표시 규칙
- 업무 1건 = 그 주 안에서 **한 줄(레인)** 을 차지하고 시작~종료 요일 칸을 프로젝트 색(연한 톤)으로 칠함
- 글자는 막대 첫 칸에만: `[P001] 원료검토` (진행 중이면 `60%` 추가)
- **주가 바뀌면 끊어짐**: 금요일에서 다음 주로 이어지면 끝에 `▶`, 다음 주 첫 칸에 `◀` 표시
- 상태별 모양
  | 상태 | 모양 |
  |------|------|
  | 예정 | 연한 색, 글자 회색 |
  | 진행 | 연한 색 + 진척률 표시 |
  | 완료 | 회색 막대, 글자 앞 `✓` |
  | 지연 (종료일 지남 & 미완료) | 빨간 테두리, 글자 앞 `⚠` |
  | 보류 | 빗금 무늬 |
  | 팀장 코멘트 있음 | 글자 앞 `💬` |
  | 승인 전 임시 프로젝트 | 코드 뒤 `*` |
- 휴가·출장·교육: 해당 날짜 칸 전체를 연회색, 막대 대신 `휴가` 글자
- 오늘: 날짜 칸 굵은 테두리 / 공휴일: 날짜 빨간색 + 공휴일명 / 다른 달 날짜: 흐리게

#### 레인(줄) 자동 배치 알고리즘
```
각 주마다:
  1) 그 주와 기간이 겹치는 Task 수집 (휴가·취소 제외)
  2) 정렬: 우선순위(상→하) → 시작일 → 기간 긴 순
  3) 각 Task를 “그 주의 표시 요일 구간에 비어 있는 가장 위 레인”에 배치
  4) 5개 레인이 다 차면 → 해당 날짜 칸 머리에 `+n건`, 셀 메모에 전체 목록
```
→ 같은 업무는 한 주 안에서 항상 같은 줄에 이어져 보이고, 중요한 업무가 위에 온다.

#### 주간 요약 칸 (H열, 자동)
- `완료 n │ 진행 n │ 지연 n`
- **금주 완료**: 이번 주에 완료 처리된 Task
- **차주 예정**: 다음 주에 시작·진행 예정인 Task (시작일 표시)
- **지연·임박**: `⚠원료검토 D+2`, `⏰보고서 D-1`
- 이 내용이 그대로 `WeeklyReport`의 초안이 된다

#### 주차 규칙
- 주 시작 = **월요일** (Setting에서 변경 가능), 주차 = “그 주 **목요일**이 속한 달의 n주차” (회사 규칙에 맞춰 설정)
- 달력은 해당 월 1일이 포함된 주부터 말일이 포함된 주까지 표시 (앞뒤 달 날짜는 흐리게, 업무는 그대로 표시)

#### 인쇄·보기
- 인쇄 영역 A4 가로 1장, 버튼 줄은 인쇄 제외
- 틀 고정(1~3행), 확대/축소해도 격자 유지
- 색상은 프로젝트마스터의 표시색 사용 (연한 톤 자동 변환) → 팀장 화면과 색이 같음

### 3.4 입력 방법 (한 가지로 통일)
- **캘린더 더블클릭**
  - 빈 막대 칸/날짜 → `frmTask` 새 등록 (시작일=그 날짜)
  - 막대 위 → 같은 폼이 **수정 모드**로 열림 (삭제 버튼 포함)
  - 보고 줄 → Milestone이 체크된 상태로 새 등록
  - 메모 줄 → 그냥 셀 편집 (폼 없음)
- 폼 항목: 프로젝트▼ / 단계▼ / 업무명 / 시작일 / 종료일 / 진척률▼ / 상태▼ / 우선순위▼ / 메모
- 프로젝트▼ 목록 맨 아래 **`[+ 새 프로젝트 요청]`** → 작은 창(프로젝트명·예상 기간·메모) → 임시 코드 발급 후 바로 선택됨 (4.6)
- 수정 모드에서 팀장 코멘트가 있으면 폼 상단에 노란 띠로 표시
- [저장] → TaskDB 기록 → 캘린더 즉시 갱신
- 여러 건을 한 번에 고칠 때는 TaskDB 표에서 직접 수정 가능 (파일 저장 시 캘린더 자동 갱신)

#### 주간보고 초안 (`WeeklyReport` 시트)
- `[주간보고]` 버튼 → 기준 주(기본: 이번 주) 선택 → 프로젝트별로 정리된 텍스트 생성
```
■ 10월 2주차 주간보고 (홍길동, 10/5~10/9)
[P001 저도주 신제품 개발]
  - 금주: 원료검토 완료, 배합시험A 진행(40%)
  - 차주: 배합시험A 완료 예정(10/14), 관능평가 착수(10/13~)
  - 이슈: 원료 입고 지연으로 원료검토 2일 지연
[P002 신제품 개발]
  - 금주: 성분분석 진행(60%)
  - 차주: 성분분석 완료 예정(10/12)
```
- 표 형식(프로젝트 │ 금주 실적 │ 차주 계획 │ 이슈) 과 텍스트 형식 두 가지를 같은 시트에 만들어 **복사·붙여넣기**만 하면 됨
- 이슈는 Task의 Note(메모)에서 자동으로 가져옴

### 3.5 자동 동작
| 시점 | 동작 |
|------|------|
| 파일 열 때 | 이번 달 캘린더 표시(이번 주로 스크롤), 팀 공통 보고일정 갱신, `Master\ProjectList.xlsx`에서 ① 프로젝트 목록 갱신 ② **임시 코드 → 정식 코드 자동 교체**, 반려 알림 ③ **팀장 코멘트 반영** (실패해도 캐시로 계속 사용) |
| TaskDB 수정 시 | LastUpdated 기록, 자동 보정 |
| 저장 시 | 캘린더 갱신 |

## 4. 팀장 파일 (`연구팀_Master.xlsm`)

### 4.1 시트 (6개)
| 시트 | 역할 |
|------|------|
| `Dashboard` | 첫 화면: KPI, 전체·프로젝트별 진척, 담당자별 업무량, 이번 주 마감, 지연 업무 |
| `ProjectView` | 프로젝트 1개 선택 → 요약 + 담당자/Task Gantt (별도안의 ProjectDashboard + ProjectSchedule 통합) |
| `TeamSchedule` | 팀원(행) × 날짜(열) 월간 일정, 휴가·부재 표시 |
| `TaskAll` | 전체 팀원 Task 통합 데이터 (표 `tblAll`) + **팀장 코멘트 열** (4.7) |
| `ProjectMaster` | 위: 정식 프로젝트 표 `tblProject` (ID·명·PM·기간·Phase 목록·상태) / 아래: **승인대기 표 `tblRequest`** (4.6) |
| `Setting` | 공유폴더 경로, 공휴일, 기준값 + **SyncLog** 영역 |

### 4.2 [전체 동기화] 버튼 – 이것 하나로 끝
```
1. Member 폴더에서 *_업무일정.xlsm 자동 검색
2. 각 파일을 읽기 전용으로 열기 → TaskDB + 프로젝트 요청(tblMyRequest) 읽기 → 즉시 닫기
3. 실패한 파일은 TaskAll의 해당 담당자 “이전 데이터 유지”
4. TaskAll 교체, TaskID 중복 검사
5. 이전 TaskAll과 비교해 신규/수정/삭제 건수 계산
6. 진척률·지연 계산 → Dashboard / ProjectView / TeamSchedule 자동 갱신
7. 새 프로젝트 요청을 ProjectMaster 승인대기에 추가 (이미 있는 요청은 건너뜀)
8. ProjectList.xlsx 자동 내보내기 (정식 목록 + 코드 교체표 + 팀장 코멘트)
9. 결과창 표시 + SyncLog 기록
```
결과창 예시
```
업무일정 동기화                 2026-09-28 08:42
김OO  ✓ 23건     이OO  ✓ 18건
박OO  ! 읽기 실패 (이전 데이터 유지, 9/25 기준)
최OO  ✓ 21건
총 89건 │ 신규 4 │ 수정 8 │ 삭제 1 │ 지연 6
새 프로젝트 요청 2건 → [승인대기 보기]
```

│ 팀 전체 진척률  ████████░░ 73% │ [지연 업무]                        │
│                              │ ⚠ P001 원료검토   김OO 9/20 40%  │
│ [프로젝트별 진척]              │ ⚠ P003 공정테스트 이OO 9/21 70%  │
│ P001 저도주 ███████░░ 72%     │                                  │

- 막대는 **조건부서식 데이터 막대**로 구현 (차트 개체보다 빠르고 깨지지 않음)
- 프로젝트명 클릭 → ProjectView로 이동하며 해당 프로젝트 자동 선택
- “미갱신”: LastUpdated가 7일 이상 지난 진행 Task를 가진 팀원 수
- 승인대기 프로젝트가 있으면 KPI 줄 오른쪽에 `📥 프로젝트 요청 2` 표시 (클릭 → ProjectMaster 승인대기)
- 승인 전 임시 프로젝트의 Task도 프로젝트별 진척에 **“미승인 프로젝트”** 묶음으로 표시 → 누락 없음

### 4.4 ProjectView
- 상단 `[P001 저도주 신제품 개발 ▼]` (데이터 유효성 목록) → 선택 즉시 아래 전체 갱신
- 요약: 진척률, (2단계) 계획진척률·차이, 참여 담당자, Task 전체/완료/진행/지연
- Gantt: 행 = Phase → Task(담당자), 열 = 날짜(최대 8주) 또는 주(최대 26주)
  - 계획기간 연한색, 진척 부분 진한색, 오늘 세로선, 지연 Task 빨간 끝 표시

### 4.5 TeamSchedule
- 월 선택 → 행: 팀원, 열: 1~31일, 값: 그날 진행 중인 ProjectID (`P001,P003`), 휴가는 `휴가`
- 셀 선택 시 해당 Task 목록 표시(셀 메모)
- 맨 아래 “부재 인원” 행 → 회의·출장 일정 잡을 때 사용

### 4.6 팀원 프로젝트 요청 → 팀장 승인 흐름
**원칙: 정식 프로젝트 목록은 팀장만 관리하되, 팀원이 기다리지 않도록 “임시 프로젝트”로 먼저 일하게 한다.**

```
[팀원] 입력폼 [+ 새 프로젝트 요청]
   │  프로젝트명 / 예상 기간 / 메모 입력
   ▼
임시 코드 N-김OO-01 발급 → 바로 Task 등록·캘린더 표시 가능
   │  (팀원 파일 Setting의 tblMyRequest 에 기록, 파일 저장)
   ▼
[팀장] [전체 동기화] → 결과창 “새 프로젝트 요청 2건”
   │  ProjectMaster 승인대기(tblRequest)에 자동 추가
   ▼
팀장이 처리 방법 선택 (승인대기 행의 [처리▼] 드롭다운 + [처리 적용] 버튼)
   ├─ 승인      : 정식 코드(P005) 발급, 이름·기간·PM·Phase 수정 가능 → tblProject에 추가
   ├─ 기존 통합 : 기존 프로젝트(P001) 선택 → 그 프로젝트의 Task로 합쳐짐
   └─ 반려      : 사유 입력
   ▼
ProjectList.xlsx 의 CodeMap 에 “N-김OO-01 → P005 / P001 / 반려” 기록
   ▼
[팀원] 다음에 파일 열 때 자동 처리
   ├─ 승인·통합 : TaskDB의 N-김OO-01 을 P005(P001)로 일괄 교체, “프로젝트가 승인되었습니다” 알림
   └─ 반려      : 해당 Task에 반려 사유 표시, 다른 프로젝트로 옮기도록 안내 (Task는 지우지 않음)
```

**승인대기 표 (`ProjectMaster` 아래, `tblRequest`)**
| 요청코드 | 요청자 | 프로젝트명(요청) | 예상 기간 | 메모 | 연결 Task 수 | 요청일 | 처리▼ | 정식코드/통합대상 | 반려 사유 | 처리일 |
|---|---|---|---|---|---|---|---|---|---|---|
| N-김OO-01 | 김OO | 저도주 향 개선 | 10/1~11/30 | 긴급 요청 | 3 | 9/28 | 승인 | P005 | | 9/28 |
| N-이OO-01 | 이OO | 원료 A 검토 | 10/5~10/20 | | 1 | 9/28 | 기존 통합 | P001 | | 9/28 |

**설계 포인트**
- 임시 코드는 `N-이름-순번` → 팀원끼리 코드가 겹치지 않음
- 승인 전에도 대시보드에 “미승인 프로젝트”로 집계 → 팀장이 모르는 업무가 생기지 않음
- 팀원이 같은 요청을 두 번 올려도 요청코드 기준으로 한 번만 등록
- 처리 결과는 CodeMap에 계속 남으므로, 팀원이 한동안 파일을 안 열었다가 열어도 정상 교체됨
- 팀장은 **정식 프로젝트는 언제든 수정 가능** (이름·기간·PM·Phase·종료 처리). 코드(P005) 자체는 바꾸지 않는 것을 원칙으로 함

### 4.7 팀장 코멘트 (팀장 → 팀원 전달)
팀장은 팀원 파일을 **직접 수정하지 않는다** (팀원이 파일을 열고 있을 때 충돌·덮어쓰기 방지). 대신 코멘트를 보낸다.

```
[팀장] Dashboard 지연목록 / ProjectView / TaskAll 에서 Task 행의 “팀장 코멘트” 칸에 입력
       예) “9/30까지 당겨주세요”, “P003 결과 먼저 공유 바랍니다”
   ▼
[전체 동기화] 또는 [코멘트 보내기] → ProjectList.xlsx 의 Comments(TaskID, 코멘트, 작성일)
   ▼
[팀원] 파일 열 때 TaskDB Q열(LeaderComment)에 반영
       캘린더에 💬 표시, 파일 열 때 “새 팀장 코멘트 2건” 알림, 입력폼 상단에 노란 띠
```
- 코멘트는 TaskID 기준으로 저장 → 재동기화해도 사라지지 않음
- 팀원 답변은 기존 Note(메모) 칸 사용 → 다음 동기화 때 팀장 화면에 표시 (별도 기능 불필요)
- 코멘트를 지우면 팀원 쪽에서도 다음에 열 때 지워짐

### 4.8 권한 정리
| 대상 | 팀장 | 팀원 |
|------|------|------|
| 정식 프로젝트 (추가·수정·종료) | ✅ ProjectMaster에서 | ❌ (선택만) |
| 임시 프로젝트 요청 | 승인 / 기존 통합 / 반려 | ✅ 입력폼에서 생성, 승인 전까지 사용 |
| 팀원 Task 내용 | 👁 조회 + 💬 코멘트 | ✅ 본인 파일에서 추가·수정·삭제 |
| 팀장 코멘트 | ✅ 작성·삭제 | 👁 조회 (답변은 Note 칸) |

### 4.9 팀 공통 보고일정 (팀장 → 모든 팀원 캘린더)
- Master `Setting`의 `tblTeamEvent` 표에 팀 공통 일정을 등록: 날짜 / 시간 / 제목 / 대상(전체·특정 팀원) / 반복(매주 월, 매월 말일 등)
  - 예: 주간회의(매주 월 10시), 주간보고 제출(매주 금), 월간보고(매월 마지막 금), 과제 중간발표(11/20)
- 동기화 시 `ProjectList.xlsx`의 Events 시트로 내보냄 → 팀원 파일이 열릴 때 캘린더 **보고 줄**에 `◆` 로 자동 표시
- 팀원은 따로 입력하지 않아도 팀 보고 일정이 모두 자기 캘린더에 뜬다
- Master `TeamSchedule`·`ProjectView`에도 같은 ◆ 표시

## 5. 계산 기준

### 5.1 진척률 (두 안 공통 → 확정)
```
Task 가중치(PlanDays) = 공휴일 제외 작업일수 (자동)
프로젝트 진척률 = Σ(PlanDays × 진척률) ÷ Σ(PlanDays)
팀 전체 진척률 = Σ(프로젝트 PlanDays합 × 프로젝트 진척률) ÷ Σ(전체 PlanDays)
```
예) 원료검토 2일 100%, 배합시험 5일 60%, 관능평가 3일 30% → (200+300+90)÷10 = **59%**
- 휴가·취소·`공통`은 진척 계산에서 제외 (일정 표시만)

### 5.2 지연 판정 (자동, 사람이 고르지 않음)
| 표시 | 조건 | 단계 |
|------|------|------|
| ⚠ 지연 | 오늘 > DueDate AND 진척률 < 100 | 1단계 |
| ⏰ 마감임박 | DueDate까지 3영업일 이내 AND 진척률 < 80 | 1단계 |
| 🟡 계획 대비 늦음 | 실제 − 계획 진척 ≤ −15%p | 2단계 |

### 5.3 계획진척률 (2단계)
```
계획진척 = 오늘까지 경과 작업일 ÷ 전체 작업일  (시작 전 0%, 종료 후 100%)
프로젝트 계획진척 = Σ(PlanDays × 계획진척) ÷ Σ(PlanDays)
```

> 모든 팀원 파일의 코드는 Template 하나에서만 관리. Setting에 `버전`을 두고, Master가 구버전 파일을 결과창에 표시.

### 핵심 코드 골격 – 수집 (실패 시 이전 데이터 유지)
```vba
' modSync
Public Sub SyncAll()
    Dim f As String, owner As String, data As Variant
    Dim newAll As Collection: Set newAll = New Collection
    SpeedOn
    f = Dir(GetSetting("MemberFolder") & "\*_업무일정.xlsm")
    Do While f <> ""
        owner = Split(f, "_")(0)
        data = ReadTaskDB(GetSetting("MemberFolder") & "\" & f)
        If IsArray(data) Then
            newAll.Add data
            AddResult owner, "✓", UBound(data, 1) & "건"
        Else
            newAll.Add PreviousRowsOf(owner)            ' 이전 데이터 유지
            AddResult owner, "!", CStr(data) & " (이전 데이터 유지)"
        End If
        f = Dir()
    Loop
    CollectRequests                                     ' 새 프로젝트 요청 → 승인대기
    CompareWithPrevious newAll                          ' 신규/수정/삭제 건수
    WriteTaskAll newAll
    RecalcAll                                           ' 진척·지연·화면 갱신
    ExportProjectList                                   ' Projects + CodeMap + Comments
    SpeedOff
    frmSyncResult.Show
End Sub

Private Function ReadTaskDB(ByVal path As String) As Variant
    Dim wb As Workbook
    On Error GoTo EH
    Set wb = Workbooks.Open(path, UpdateLinks:=0, ReadOnly:=True, AddToMru:=False)
    With wb.Worksheets("TaskDB").ListObjects("tblTask")
        If .DataBodyRange Is Nothing Then ReadTaskDB = "Task 없음" _
        Else ReadTaskDB = .DataBodyRange.Value
    End With
    wb.Close False
    Exit Function
EH:
    ReadTaskDB = Err.Description
    If Not wb Is Nothing Then wb.Close False
End Function
```

## 7. 개발 단계 (3단계)

| 단계 | 기간 | 범위 | 완료 기준 |
|------|------|------|-----------|
| **1단계 MVP** | 약 4주 | 팀원: 주간형 월간 Calendar + 주간보고 초안 + TaskDB + 입력폼 + 자동표시 + **임시 프로젝트 요청** / 팀장: 전체 동기화 + **승인대기·처리** + TaskAll + Dashboard(KPI·프로젝트 진척·지연·금주마감·담당자 업무량) + TeamSchedule | 팀원 2~3명 파일럿으로 1주 운영 |
| **2단계 팀장 기능** | 약 2주 | **팀장 코멘트**, ProjectView(Gantt), 계획 vs 실제 진척, 신규/수정/삭제 비교, 미갱신 표시 | 주간회의를 Dashboard로 진행 |
| **3단계 고도화** | 필요 시 | 변경이력(Log), 마일스톤·선후관계, 연구 특화 열, 월간/분기 통계, **[회의자료 생성]** (진척·지연·금주완료·차주예정·이슈 → PDF) | |

1단계 세부 순서
1. 주간형 월간 달력 격자(3.3) 제작 → 팀 의견 1회 수렴(열 폭·레인 수·주차 규칙)
2. TaskDB 열 구조 확정 (3.2 표)
3. 입력폼 + 자동 보정
4. TaskDB → Calendar 자동 표시 (레인 배치·막대·주간 요약) + 주간보고 초안
5. Master: 폴더 검색·수집·결과창
6. Dashboard / TeamSchedule
7. 파일럿 2~3명 → 수정 → 전체 배포 (10분 사용법 안내 1장)

## 9. 피해야 할 설계 (두 안 공통 결론)
1. **캘린더 셀 글자를 DB로 쓰기** – `9/23 = "관능평가/김OO/60%"` 식이면 집계·검색 불가
2. **팀장 파일이 팀원 캘린더 화면을 복사** – 프로젝트별 검색·진척·지연 기능을 붙일 수 없음
3. **파일마다 다른 VBA 코드/열 구조** – 반드시 Template 하나에서 복사
4. **1차부터 모든 기능 넣기** – 입력 항목이 늘면 팀원이 갱신을 안 하게 되고, 그러면 Dashboard가 의미 없어짐
